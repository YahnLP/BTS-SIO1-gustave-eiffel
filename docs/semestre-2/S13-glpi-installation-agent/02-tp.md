### B4. Apache (≈ 10 min)

Crée le fichier `/etc/apache2/sites-available/glpi.conf` :

```apache
<VirtualHost *:80>
    ServerName glpi.local
    DocumentRoot /var/www/html/glpi/public

    <Directory /var/www/html/glpi/public>
        Require all granted
        RewriteEngine On
        RewriteCond %{HTTP:Authorization} ^(.+)$
        RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]
        RewriteCond %{REQUEST_FILENAME} !-f
        RewriteRule ^(.*)$ index.php [QSA,L]
    </Directory>
</VirtualHost>
```

```bash
sudo a2dissite 000-default.conf
sudo a2enmod rewrite
sudo a2ensite glpi.conf
sudo apache2ctl configtest
sudo systemctl restart apache2
```

**Je comprends.**

1. Pourquoi la racine du site est-elle le dossier **`public`** et non `/var/www/html/glpi` ? ______________________
2. Que fait `a2enmod rewrite` ? Pourquoi `apache2ctl configtest` **avant** le redémarrage ? ______________________

**Réglages PHP.** La documentation officielle demande aussi quelques réglages de `php.ini` (temps d'exécution, taille des envois, mémoire, cookie de session, **fuseau horaire**). Trouve le fichier (`ls /etc/php`, puis `/etc/php/<version>/apache2/php.ini`), repère les paramètres dans la page officielle, applique-les et redémarre Apache. Paramètres modifiés : ______________________

**Test T2 :** depuis le client, ouvre `http://192.168.X.1/` dans un navigateur.

<details markdown="1">
<summary>Éléments de réponse</summary>

1. Seul le dossier **public** contient ce que le navigateur doit pouvoir atteindre ; le reste (code, configuration) reste **hors de portée** du Web. C'est une mesure de sécurité.
2. Il active le module de **réécriture d'URL** (utilisé par la configuration ci-dessus). `configtest` **vérifie la syntaxe** : une erreur de configuration empêcherait Apache de redémarrer et couperait le service.

</details>

**Je cherche.** Comment **forcer** un inventaire sur le poste, sans réinstaller l'agent ? Cherche dans la documentation de l'agent ; note la méthode et la source : ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

**C1.** Le serveur **refuse** l'inventaire (ou l'ignore) : le poste n'apparaît pas. L'activation est **côté serveur**.

**C2.** 1. `RUNNOW=1` lance un inventaire **immédiatement** après l'installation. En déploiement de masse, il lancerait 200 inventaires **en même temps** (charge du serveur) ; on laisse l'agent s'exécuter à sa fréquence normale. 2. Un **service** tourne en arrière-plan, **sans session ouverte** ; il lance les inventaires à intervalles réguliers et au démarrage. 3. HTTP **sans chiffrement** : acceptable dans un laboratoire isolé ; en production, **HTTPS** avec certificat pour protéger les données de parc en transit.

**C3.** Causes fréquentes : serveur injoignable, URL avec une faute, inventaire non activé, pare-feu, agent installé sans droits. Les journaux de l'agent (dossier d'installation, sous-dossier `logs`) disent souvent la cause. La méthode pour forcer un inventaire est **à trouver dans la documentation officielle de l'agent** (option de la commande de l'agent ou interface locale) : non vérifiée ici.

</details>

## Partie F – Questions de réflexion (≈ 15 min)

1. GLPI a détecté **___** logiciels sur ton poste. Tu en avais listé **___** à la main. Comment expliques-tu l'écart ? ______________________
2. L'agent est un **service** qui s'exécute automatiquement. Cite **deux situations** où cette mise à jour automatique est utile à la DSI. ______________________
3. Ton **entreprise d'alternance** utilise-t-elle un outil d'inventaire ? Lequel ? Comment les données sont-elles exploitées ? ______________________
4. **Variante OCS.** Quelles différences d'architecture (nombre de serveurs, composants à installer) entre « agent GLPI + GLPI » et « agent OCS + OCS + plugin + GLPI » ? Dans quel cas pourrais-tu rencontrer OCS ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

1. L'inventaire automatique recense **tout ce qui est installé** (y compris composants système, bibliothèques, mises à jour), alors qu'une liste manuelle se limite à ce qu'on remarque.
2. **Mise à jour** automatique des versions (planifier les correctifs, repérer un logiciel obsolète) ; **détection** de changements (matériel retiré, logiciel non autorisé) ; **préparation d'un audit** de licences ; **retrouver** un poste après un changement de nom ou d'adresse.
3. Réponse personnelle ; accepter « je ne sais pas » et demander comment se renseigner.
4. **Un seul** serveur (GLPI) avec l'agent GLPI ; **deux serveurs** (OCS et GLPI) plus un **plugin de liaison** avec OCS. On peut rencontrer OCS dans une organisation qui l'a installé **avant** l'inventaire natif de GLPI.

</details>
