**Questions de compréhension**

1. Qu'est-ce qu'un **hyperviseur** ? ______________________
2. Qu'est-ce qu'une **machine virtuelle** ? ______________________
3. Qu'est-ce que la **virtualisation** ? ______________________
4. Fais un **schéma** et une courte description pour expliquer les **deux types de virtualisation** (deux types d'hyperviseurs). ______________________
5. Identifie **cinq catégories d'utilisation** de la virtualisation. ______________________
6. Liste quelques **avantages** et **inconvénients** de la virtualisation. ______________________
7. Quelles sont les **deux façons** d'installer une machine virtuelle ? Utilise les notions d'**OVA**, d'**OVF** et d'**ISO**. ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

1. Un logiciel qui crée des ressources virtuelles et répartit les ressources physiques entre plusieurs machines virtuelles, en les isolant.
2. Un ordinateur simulé à l'intérieur d'un autre, qui utilise les ressources de la machine hôte.
3. La technique qui permet de faire fonctionner plusieurs systèmes isolés sur une même machine physique.
4. Type 2 : matériel, système hôte, hyperviseur, VM. Type 1 : matériel, hyperviseur, VM. Voir le schéma du cours.
5. Par exemple : tester un système sans formater le poste ; lancer une application propre à un système ; simuler un petit réseau (pare-feu, serveurs) ; apprendre l'administration sans risque pour le poste principal ; consolider des serveurs en production ; préproduction ; sauvegardes et migrations.
6. Avantages : moins de matériel, tests sans risque, restauration facile. Inconvénients : ressources partagées avec l'hôte, performances moindres en type 2, dépendance à la machine hôte (si elle tombe, les VM tombent).
7. Créer une VM « nue » et installer un système depuis une ISO, ou importer un fichier OVA (paquet complet) ou OVF (description seule, avec un fichier disque).

</details>

## Partie B – Créer la machine virtuelle Windows (≈ 25 min)

**But :** créer une VM avec une configuration imposée.

1. Lance **VirtualBox** sur ton poste.
2. Clique sur **Nouvelle** et configure la machine avec les valeurs ci-dessous.

| Réglage | Valeur imposée | Je comprends : cela représente… |
|---|---|---|
| Nom de la VM | `CS1 - W10 - NOM` (ton nom) | |
| Emplacement | Disque indiqué par l'enseignant | |
| Type | Microsoft Windows | |
| Version | Windows 10 / 11 (64 bits), selon la consigne | |
| Mémoire vive | 2 048 Mo | |
| Processeurs | 2 cœurs | |
| Stockage | Dynamiquement alloué, 50 Gio d'espace virtuel | |
| Type de disque virtuel | VMDK | |
| Réseau | Accès par pont, sur la carte reliée au réseau du lycée | |

3. **Capture d'écran n° 1** : le résumé de la configuration dans VirtualBox.

**J'anticipe.** Le disque virtuel fait 50 Gio mais il est « dynamiquement alloué ». Quelle taille aura le fichier sur ton disque physique **juste après la création** ? Plus tard, quand Windows sera installé ? ______________________

**Je comprends.**

1. Quelle est la différence entre le **stockage physique** et le **stockage virtuel** ? ______________________
2. Quelle est la différence entre les types de disque virtuel **VDI** et **VMDK** ? ______________________
3. Pourquoi avoir choisi l'**accès par pont** ? Quel risque cela présente-t-il pour le réseau du lycée ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

1. Le stockage physique est un vrai disque ou SSD. Le stockage virtuel est un **fichier** enregistré sur le disque physique de l'hôte, que la VM voit comme son propre disque.
2. Ce sont deux formats de fichier de disque virtuel : VDI est celui de VirtualBox, VMDK est le format historique de VMware (VirtualBox sait le lire).
3. En accès par pont, la VM se comporte comme une machine du réseau, avec sa propre adresse : elle est joignable par d'autres machines. C'est moins sécurisé, car la VM est exposée sur le réseau réel, et certains réseaux refusent de donner une adresse à une VM.

Sur la taille : avec un stockage dynamique, le fichier est petit à la création et **grossit** avec les données écrites, jusqu'à la limite de 50 Gio.

</details>

## Partie C – Créer l'ISO Windows, si nécessaire (≈ 15 min)

**But :** obtenir une image d'installation. Si l'enseignant fournit déjà l'ISO, passe à la partie D.

1. Récupère l'outil de création de média sur le site officiel de Microsoft (adresse donnée par l'enseignant).
2. Lance-le et choisis de **créer un fichier ISO**, en **français**, en **64 bits**.
3. Enregistre l'ISO sur **ton espace personnel ou un disque externe, pas sur `C:`**.
4. **Capture d'écran n° 2** : le fichier ISO créé, avec son emplacement et sa taille.

**Je comprends.** Qu'est-ce qu'un fichier **ISO** ? Pourquoi télécharger l'outil **sur le site officiel** et pas ailleurs ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

Une ISO est l'image d'un disque optique (CD ou DVD) dans un seul fichier : elle sert à installer un système, comme si on insérait le disque. On passe par le site officiel pour éviter un fichier modifié (virus, scripts cachés).

</details>

## Partie D – Installer le système (≈ 40 min)

**But :** installer Windows dans la VM à partir de l'ISO.

1. Dans les paramètres de la VM, ajoute un emplacement de stockage de type **disque optique** dans le contrôleur **SATA**, et sélectionne ton **ISO**.
2. **Capture d'écran n° 3** : les emplacements de stockage de la VM.
3. Démarre la VM et lance l'installation. Choisis la langue de ton choix.
4. Configure l'installation ainsi :
    - pas de clé de produit ;
    - édition Windows Home (ou Pro, selon la consigne) ;
    - installation **avancée** ;
    - crée **une deuxième partition de 20 Go** sur le disque virtuel (en plus de celle du système).
5. Prépare l'environnement Windows :
    - langue : français ;
    - profil de compte **hors ligne** ;
    - refuse les options de personnalisation ;
    - nom du système : `sisr` ;
    - mot de passe : celui **donné par l'enseignant**.
6. **Capture d'écran n° 4** : le résultat (bureau ou première ouverture).

**J'anticipe.** Pourquoi l'ISO est-elle ajoutée **dans un contrôleur de stockage** et pas simplement « ouverte » dans VirtualBox ? ______________________

**Je comprends.**

1. Combien y a-t-il d'**emplacements de stockage** sur ta VM ? Quel est le rôle de chacun ? ______________________
2. Pourquoi est-il préférable, pour la sécurité, de créer **deux espaces de stockage** sur le système ? ______________________
3. Pourquoi refuse-t-on les options de personnalisation et le compte en ligne dans cette configuration ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

1. Deux : le **disque dur virtuel** (système et données de la VM) et le **lecteur optique virtuel** (qui contient l'ISO d'installation).
2. Séparer le système des données facilite la **réinstallation** du système sans toucher aux données, et les **sauvegardes**. On peut aussi appliquer des droits différents à chaque espace.
3. Les paramètres d'origine du support imposent un profil hors ligne ; cela évite d'associer la VM de test à un compte personnel. L'enseignant précise le motif attendu.

</details>

**Je comprends.** Compare avec ta prévision. Que peux-tu conclure sur le **fonctionnement de la virtualisation** et d'où viennent les ressources de la VM ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

La mémoire utilisée par l'hôte augmente d'environ ce qui a été attribué à la VM (ici 2 048 Mo, plus le fonctionnement de l'hyperviseur) ; le processeur et le disque sont davantage sollicités, surtout au démarrage. La VM n'a aucune ressource propre : tout est **prélevé sur l'hôte**.

</details>
