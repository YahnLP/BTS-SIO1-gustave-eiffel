## Partie A – Préparer l'environnement (≈ 30 min)

**But :** disposer d'une machine Debian prête, joignable sur le réseau du lycée.

1. Lance **VirtualBox** sur ton poste.
2. Importe l'appareil virtuel **OVA** Debian fourni (ou duplique la machine Debian existante, selon la consigne de l'enseignant). La VM doit être installée sur le disque indiqué par l'enseignant.
3. Renomme la VM : `CS1 – Debian – NOM` (ton nom).
4. Règle la carte réseau de la VM en **accès par pont**, sur la carte de ton poste reliée au réseau du lycée.
5. Démarre la VM et ouvre une session.

**J'anticipe.** Quelle différence y a-t-il entre le mode **NAT** et l'**accès par pont** ? Pourquoi choisir le pont ici ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

En **NAT**, la VM est cachée derrière l'adresse du poste hôte : elle sort sur le réseau mais n'est pas joignable de l'extérieur sans redirection. En **accès par pont**, la VM se comporte comme une machine à part entière du réseau du lycée, avec sa propre adresse : elle peut être jointe par un serveur ou un autre poste, ce qui est le cas d'un vrai serveur de fichiers.

</details>

## Partie B – Observer la machine (≈ 40 min)

**But :** utiliser le terminal pour lire l'état de la machine et retrouver ses propres commandes.

### B1. `sudo` et `root`

| Étape | Je fais | J'anticipe | Je constate |
|---|---|---|---|
| 1 | Taper `sudo reboot` | | |
| 2 | Après le redémarrage, **chercher** (avec `man` ou `--help`) une commande pour **ouvrir une session root**, puis la taper et en sortir avec `exit` | | |

**Je comprends.**

1. À quoi correspond la commande `sudo` ? ______________________
2. Que signifie **root** sous Linux ? Quelle est la différence entre une commande lancée avec `sudo` et une session root ? ______________________
3. Pourquoi demande-t-on, en entreprise, de préférer `sudo` à une session root permanente ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

1. `sudo` exécute **une** commande avec les droits d'un autre utilisateur, par défaut `root`, après avoir demandé **le mot de passe de l'utilisateur** qui l'emploie.
2. `root` est l'administrateur, qui peut tout faire. Avec `sudo`, les droits ne durent que le temps d'une commande ; une session root les donne pour toute la session.
3. Les erreurs sont limitées à une commande à la fois, et chaque usage de `sudo` laisse une trace dans les journaux.

</details>

|---|---|---|---|
| `df -h` | | | |
| `du -sh ~` | | | |

**Je comprends.** Que changent les options `-h` (de `df`, `du`) et `-m` (de `free`) ? Teste `df` puis `free` **sans** option et compare. ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

`-h` (« human-readable ») affiche les tailles dans une unité lisible (Ko, Mo, Go). Sans option, `df` et `du` comptent en blocs, et `free` en kilo-octets : les nombres sont bien plus grands et plus difficiles à lire. `-m` demande à `free` d'afficher en mégaoctets.

</details>

## Partie C – Se déplacer, créer, supprimer (≈ 40 min)

**But :** se repérer dans l'arborescence et comprendre qui a le droit d'écrire où.

### C1. Explorer

| Étape | Je fais | J'anticipe | Je constate |
|---|---|---|---|
| 7 | Taper `pwd` | | |
| 8 | Taper `cd /`, puis `pwd`. **Capture d'écran** | | |
| 9 | Taper `ls`, puis `ls -l`. **Capture d'écran** | | |
| 10 | Se déplacer dans le dossier `home` (avec un chemin **relatif**). **Capture d'écran** | | |
| 11 | **Revenir au dossier précédent** sans retaper un chemin complet | | |

**Je comprends.**

1. Qu'appelle-t-on la **racine** sous Linux ? Que représente `/` ? ______________________
2. Quelle différence y a-t-il entre `ls` et `ls -l` ? ______________________
3. À l'étape 11, quelles commandes permettent de revenir en arrière ? Donnent-elles toujours le même résultat ? Pourquoi ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

1. La racine est le point de départ de **toute** l'arborescence : tous les dossiers et fichiers sont à l'intérieur.
2. `ls -l` ajoute le type, les droits, le propriétaire, le groupe, la taille et la date de chaque élément.
3. `cd ..` remonte au dossier **parent** ; `cd -` retourne au dossier où l'on **était juste avant**. Ils donnent le même résultat seulement quand le dossier précédent est aussi le dossier parent.

</details>

### C2. Créer et supprimer

| Étape | Je fais | J'anticipe : ça va… | Je constate |
|---|---|---|---|
| 12 | Se placer dans le dossier **`/home`** (pas ton dossier personnel). Créer un dossier `GuyTare` | marcher / échouer ? Pourquoi ? | |
| 13 | Recommencer en ajoutant `sudo` devant la commande. **Capture d'écran** | | |
| 14 | **Supprimer** le dossier `GuyTare`. **Capture d'écran** | | |

**Je comprends.**

1. Si l'étape 12 a échoué, que dit le message d'erreur ? Pourquoi `sudo` règle-t-il le problème ? ______________________
2. Quelle commande as-tu utilisée pour supprimer, et pourquoi pas l'autre (`rmdir` ou `rm -r`) ? ______________________
3. Pourquoi est-il risqué de supprimer **sans** avoir vérifié `pwd` et `ls` ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

1. Le message est du type « Permission denied » (permission refusée) : `/home` appartient à `root`, et un utilisateur ordinaire ne peut pas y créer de dossier. `sudo` exécute la commande avec les droits de `root`.
2. `rmdir` supprime un dossier **vide** (et refuse sinon) ; `rm -r` supprime le dossier **et tout son contenu**. Pour un dossier vide, `rmdir` est le plus prudent.
3. Il n'y a pas de corbeille : une suppression au mauvais endroit est définitive.

</details>

## Partie D – Construire l'arborescence de JackCelair (≈ 50 min)

**But :** créer, dans `/var/partage`, l'arborescence suivante, avec un minimum de commandes.

### D3. Je vérifie

Affiche l'arborescence que tu as créée avec `ls -R /var/partage/JackCelair` et **compare-la** avec le modèle.

- [ ] Les 12 dossiers existent (JackCelair compris).
- [ ] Les noms sont **exacts** (espaces et accents).
- [ ] Les sous-dossiers sont **au bon niveau** : `vente` et `relation client` dans `commerce` ; `développeur`, `mécanicien` et `expert technique` dans `etudes`.
- [ ] J'ai une **capture d'écran** du résultat final.

**Je comprends.**

1. Pourquoi `sudo` est-il nécessaire dans `/var` ? ______________________
2. Pourquoi une erreur sur un espace (par exemple `mkdir relation client`) ne produit-elle pas de message d'erreur, alors que le résultat est faux ? ______________________
3. Une fois l'arborescence créée, qui peut y écrire ? Qui devrait pouvoir y écrire, d'après la demande de JackCelair ? (Tu y reviendras en S09.) ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

1. `/var` appartient à `root` ; seul l'administrateur peut y créer des dossiers.
2. Le shell accepte la commande : il crée simplement **deux** dossiers, `relation` et `client`. Aucune règle n'est violée, c'est le résultat qui ne correspond pas à l'attendu. C'est pourquoi on **vérifie** toujours après avoir créé.
3. Les dossiers créés avec `sudo` appartiennent à `root` : un utilisateur ordinaire ne peut pas y écrire. JackCelair veut des **habilitations par service** : chaque équipe n'accède qu'à son dossier. Les droits et les groupes seront traités en S09.

</details>
