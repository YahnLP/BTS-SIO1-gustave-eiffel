<details markdown="1">
<summary>Éléments de réponse</summary>

1. Le processeur chauffe beaucoup en travaillant ; le radiateur et le ventilateur évacuent cette chaleur, sinon le processeur ralentit pour se protéger.
2. On le voit au nombre d'emplacements (slots) libres autour des barrettes installées ; le nombre maximal et le type de mémoire acceptés se trouvent dans la documentation de la carte mère.
3. Le processeur contient souvent un **circuit graphique intégré**, qui partage la RAM de la machine. C'est suffisant pour la bureautique, moins pour la 3D ou le montage vidéo.

</details>

## Partie C – La machine papier : exécuter un programme à la main (≈ 40 min)

**But :** comprendre le cycle *chercher – décoder – exécuter* en le jouant toi-même.

### La machine

C'est une machine **imaginaire et très simplifiée**, inventée pour ce TP. Elle a deux registres, **A** et **B**, et un **compteur ordinal** (PC). Sa mémoire contient les instructions **et** les données.

| Instruction | Effet |
|---|---|
| `CHARGER R, [x]` | le registre R reçoit le contenu de la case mémoire x |
| `AJOUTER A, B` | A reçoit A + B |
| `RANGER A, [x]` | la case mémoire x reçoit le contenu de A |
| `STOP` | la machine s'arrête |

**Règle du cycle.** À chaque tour : (1) **chercher** l'instruction à l'adresse indiquée par PC, (2) **faire avancer PC de 1**, (3) **décoder** puis **exécuter**.

**Mémoire au départ :**

| Adresse | Contenu |
|---|---|
| 1 | `CHARGER A, [20]` |
| 2 | `CHARGER B, [21]` |
| 3 | `AJOUTER A, B` |
| 4 | `RANGER A, [22]` |
| 5 | `STOP` |
| 20 | 5 |
| 21 | 3 |
| 22 | *(vide)* |
| 23 | 2 |

**J'anticipe.** Avant de dérouler : que contiendra la case 22 à la fin ? ______________________

### C1. Dérouler

Au départ, PC = 1. Complète une ligne par tour :

| Tour | PC lu | Instruction | A après | B après | PC après | Case 22 |
|---|---|---|---|---|---|---|
| 1 | 1 | `CHARGER A, [20]` | | | | |
| 2 | | | | | | |
| 3 | | | | | | |
| 4 | | | | | | |
| 5 | | | | | | |

### C2. Comprendre

1. Où se trouve le **programme** ? Où se trouvent les **données** ? ______________________
2. Dans ton tableau, quel élément a « fait » l'addition ? Quel élément a décidé de l'instruction à lancer ? ______________________
3. **Sans toucher aux instructions**, change le contenu des cases 20 et 21 (par 10 et 4). Que contient la case 22 après un nouveau déroulé ? ______________________
4. **Écris** un nouveau programme (adresses 1 à 7) qui calcule `[20] + [21] + [23]` et range le résultat dans la case 22. ______________________
5. Avant Von Neumann, que fallait-il faire pour changer de calcul ? Qu'est-ce qui a changé avec l'idée du programme en mémoire ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

**C1.**

| Tour | PC lu | Instruction | A après | B après | PC après | Case 22 |
|---|---|---|---|---|---|---|
| 1 | 1 | `CHARGER A, [20]` | 5 | – | 2 | vide |
| 2 | 2 | `CHARGER B, [21]` | 5 | 3 | 3 | vide |
| 3 | 3 | `AJOUTER A, B` | 8 | 3 | 4 | vide |
| 4 | 4 | `RANGER A, [22]` | 8 | 3 | 5 | 8 |
| 5 | 5 | `STOP` | 8 | 3 | – | 8 |

**C2.**

1. Programme et données sont dans la **même mémoire** (adresses 1 à 5 pour le programme, 20 à 23 pour les données) : c'est le principe de Von Neumann.
2. L'**UAL** fait l'addition ; l'**unité de contrôle**, aidée du compteur ordinal, choisit l'instruction à lancer.
3. 14, sans modifier le programme : seules les données changent.
4. Une solution : `1 CHARGER A,[20]` ; `2 CHARGER B,[21]` ; `3 AJOUTER A,B` ; `4 CHARGER B,[23]` ; `5 AJOUTER A,B` ; `6 RANGER A,[22]` ; `7 STOP`. Résultat : 5 + 3 + 2 = 10.
5. Il fallait **recâbler** la machine. Avec le programme en mémoire, il suffit de **charger un autre programme** : une même machine fait tous les calculs, ce qui sépare le matériel du logiciel.

</details>

**Je comprends.** Cette machine fait une addition en cinq tours. Un processeur réel en fait des milliards par seconde. Qu'est-ce qui, dans le cours, peut malgré tout le ralentir ? ______________________

## Partie D – Du pseudo-code au langage machine (≈ 10 min)

Le cours montre le même calcul à quatre niveaux. Ici, tu les mets en relation avec la machine papier.

| Niveau | Ligne |
|---|---|
| Pseudo-code | `c ← a + b` |
| Python | `c = a + b` |
| Machine papier | `CHARGER A, [20]` · `CHARGER B, [21]` · `AJOUTER A, B` · `RANGER A, [22]` |

1. Combien d'instructions de la machine papier pour **une seule** ligne de Python ? ______________________
2. Pourquoi les programmeurs écrivent-ils en Python plutôt qu'en instructions de ce type ? ______________________
3. Quel type de programme traduit le Python pour que le processeur le comprenne ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

1. Quatre (deux chargements, une addition, un rangement).
2. Ces instructions sont trop élémentaires : un programme réel demanderait des milliers de lignes, difficiles à écrire, à relire et à corriger ; un langage évolué est plus court et plus lisible.
3. Un **interpréteur** (Python traduit au fur et à mesure) ou un **compilateur** (traduction avant exécution).

</details>
