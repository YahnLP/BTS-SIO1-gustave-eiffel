## Partie A – Utilisateurs et groupes (≈ 40 min)

**But :** créer un compte, lui donner les droits d'administration, et comprendre où le système l'enregistre.

### A1. Créer `tech2025` et l'ajouter à `sudo`

1. Crée l'utilisateur `tech2025` : `sudo adduser tech2025` (choisis un mot de passe et note-le sur papier, pas dans le compte rendu ; tu peux laisser vides les champs d'information).
2. Ajoute-le au groupe `sudo` : `sudo usermod -aG sudo tech2025`.
3. Vérifie : `id tech2025`.
4. Ouvre une session en tant que `tech2025` : `su - tech2025`, puis `pwd` et `whoami`.

**J'anticipe.** Que va afficher `id tech2025` ? Dans quels groupes sera-t-il ? ______________________

**Je comprends.**

1. Que signifie chaque lettre de `usermod -aG` ? Que se passerait-il **sans** le `a` ? ______________________
2. Pourquoi `su -` (avec le tiret) et pas `su` tout seul ? Teste les deux et compare le dossier courant. ______________________
3. Quel mot de passe `su - tech2025` demande-t-il : le tien (utilisateur actuel) ou celui de `tech2025` ? Et `sudo` ? ______________________

### A2. Où le système enregistre-t-il tout cela ?

Affiche les fichiers suivants (avec `cat`, ou `grep tech2025` pour ne voir que ta ligne) :

```bash
grep tech2025 /etc/passwd
grep tech2025 /etc/group
```

| Fichier | Ce que je lis pour `tech2025` | Je comprends : chaque champ représente… |
|---|---|---|
| `/etc/passwd` | | |
| `/etc/group` | | |

**Je comprends.** Pourquoi `/etc/passwd` est-il lisible par tous alors que les mots de passe sont dans `/etc/shadow` (réservé à `root`) ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

Tout programme a besoin de faire correspondre un numéro d'utilisateur à un nom : `/etc/passwd` doit donc être lisible. Les mots de passe (chiffrés) sont isolés dans `/etc/shadow`, que seul `root` lit, pour qu'on ne puisse pas essayer de les casser.

Réponses précédentes : (1) `-G` définit les groupes secondaires, `-a` les **ajoute** ; sans `-a`, la liste est remplacée. (2) `su -` ouvre une vraie session de connexion : dossier courant et environnement de `tech2025` ; `su` seul garde ton environnement. (3) `su - tech2025` demande le mot de passe de `tech2025` ; `sudo` demande **le tien**.

</details>

## Partie C – Les liens (≈ 30 min)

**But :** créer un lien dur et deux liens symboliques, puis voir ce qui survit à un renommage.

1. Va dans `couleur/chaude`. **Écris une ligne** dans `rouge.txt` pour que l'affichage soit visible : `echo "rouge" > rouge.txt`.
2. Crée un **lien dur** `orange.txt` vers `rouge.txt` : `ln rouge.txt orange.txt`.
3. Crée un **lien symbolique relatif** `orangeRelatif` : `ln -s rouge.txt orangeRelatif`.
4. Crée un **lien symbolique absolu** `orangeAbsolu`, en donnant à `ln -s` le **chemin absolu** de `rouge.txt`.
5. Affiche les détails avec `ls -li`. **Capture d'écran.**
6. Remonte dans `CommandesLinux` et **renomme** le dossier `couleur` en `peinture`.
7. Retourne dans `peinture/chaude` et **essaie d'afficher** le contenu de `orange.txt`, `orangeRelatif` et `orangeAbsolu` (avec `cat`). **Capture d'écran.**
8. Liste la totalité de l'arborescence de `CommandesLinux`.

**J'anticipe.** Avant l'étape 6, prévois pour chacun des trois liens s'il fonctionnera encore après le renommage de `couleur` en `peinture`. Pourquoi ?

| Lien | Fonctionnera après le renommage ? | Pourquoi ? |
|---|---|---|
| `orange.txt` (lien dur) | | |
| `orangeRelatif` | | |
| `orangeAbsolu` | | |

**Je comprends.**

1. Que montre `ls -li` : quel numéro est identique entre `rouge.txt` et `orange.txt` ? Que signifie-t-il ? Quel est le compteur de liens de `rouge.txt` ? ______________________
2. Qu'as-tu constaté à l'étape 7 ? Compare avec ta prévision. ______________________
3. Si tu supprimes `rouge.txt`, que deviennent `orange.txt` et `orangeRelatif` ? ______________________
4. Quand préférer un lien symbolique, quand préférer un lien dur ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

1. Le **numéro d'inode** est le même : `rouge.txt` et `orange.txt` sont deux noms du même contenu. Le compteur de liens passe à 2.
2. Après le renommage : `orange.txt` fonctionne (il désigne directement les données), `orangeRelatif` fonctionne (il ne mentionne que `rouge.txt`, dans le même dossier), `orangeAbsolu` est **cassé** (le chemin `…/couleur/chaude/rouge.txt` n'existe plus).
3. `orange.txt` fonctionne toujours (les données restent tant qu'un nom les désigne) ; `orangeRelatif` est cassé (la cible n'existe plus).
4. Lien symbolique : pour désigner un **dossier** ou traverser une partition, ou quand on veut un raccourci visible vers un chemin. Lien dur : quand on veut que les données survivent à la suppression d'un des noms (dans la même partition, pour des fichiers).

</details>

### D3. L'effet des droits sur un dossier

1. Sous le compte **`tech2025`**, crée `tableau` avec `mkdir tableau`, puis `touch tableau/note.txt`.
2. Retire le droit **`x`** du dossier : `chmod u-x tableau`.
3. Essaie : `ls tableau`, `cat tableau/note.txt`, `cd tableau`.
4. Remets-le : `chmod u+x tableau`. Retire maintenant **`r`** seulement : `chmod u-r tableau`, puis `ls tableau` et `cat tableau/note.txt`.

**J'anticipe.** Dans chaque cas (sans `x`, puis sans `r`), qu'est-ce qui marchera ou non ? ______________________

**Je comprends.** Que signifient `r`, `w` et `x` sur un **dossier** ? Pourquoi `cat tableau/note.txt` fonctionne-t-il sans `r` mais échoue sans `x` ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

Sur un dossier : `r` = lister les noms, `w` = créer/supprimer des éléments, `x` = traverser (y entrer, accéder à ce qu'il contient). Sans `x`, on ne peut plus ni entrer ni lire `note.txt`, même avec `r`. Sans `r` mais avec `x`, `ls tableau` est refusé (on ne peut pas lister), mais on peut toujours atteindre un fichier **dont on connaît le nom**, donc `cat tableau/note.txt` fonctionne.

Pour le `umask` : il **retire** des droits à ceux que le système aurait donnés au maximum à la création ; la valeur exacte est à constater sur la VM. Le `x` des dossiers est nécessaire pour y entrer : les dossiers ont donc des droits plus larges que les fichiers ordinaires.

</details>

## Partie E – Les habilitations de JackCelair (≈ 50 min)

**But :** appliquer une politique de droits par service sur `/var/partage/JackCelair`, puis la **tester**.

### E1. La politique à mettre en place

Consulte la [matrice des habilitations](tp/matrice-habilitations.txt). Résumé :

- chaque **service** a un **groupe** (`grp-commerce`, `grp-etudes`, `grp-direction`, `grp-compta`, `grp-rh`, `grp-communication`) ;
- les membres d'un groupe ont **tous les droits** (`rwx`) sur le dossier de leur service **et ses sous-dossiers** ;
- **personne d'autre** n'a le moindre droit sur ce dossier ;
- les fichiers créés dans un dossier doivent **appartenir au groupe du service** ;
- le dossier `JackCelair` lui-même reste **lisible et traversable** par tous.

**J'anticipe (avant de configurer).** Avec les droits actuels (tout appartient à `root`), un utilisateur ordinaire peut-il écrire dans `commerce` ? Peut-il lire ? Pourquoi ? ______________________

**J'anticipe (la politique).** Quelles **valeurs octales** vas-tu utiliser : pour `JackCelair` ? pour les dossiers de service ? Quel chiffre ajouter devant pour que les fichiers héritent du groupe ? ______________________

### E2. Les commandes (exemple pour le service commerce)

Les commandes sont données pour **un** service ; **tu les répliques** pour les cinq autres, en adaptant les noms.

```bash
sudo addgroup grp-commerce
sudo chgrp -R grp-commerce /var/partage/JackCelair/commerce
sudo chmod -R 2770 /var/partage/JackCelair/commerce
sudo chmod 755 /var/partage/JackCelair
```

**Je comprends.** Explique chaque ligne : ______________________

| Ligne | Elle fait… | Pourquoi dans cet ordre ? |
|---|---|---|
| `addgroup` | | |
| `chgrp -R` | | |
| `chmod -R 2770` | | |
| `chmod 755` | | |

> [!NOTE]
> `chmod -R 2770` met le bit setgid sur tout le contenu. Ici, il n'y a que des **dossiers**, c'est ce qu'on veut. Sur un dossier contenant déjà des fichiers, on traiterait séparément les fichiers et les dossiers.

Réplique pour : `etudes`, `direction générale` (groupe `grp-direction`), `comptabilité` (`grp-compta`), `ressources humaines` (`grp-rh`), `communication` (`grp-communication`). **Attention aux noms avec espace** : relis S08.

| Compte | Groupe |
|---|---|

### E4. Tester, comme le ferait l'entreprise

Pour chaque ligne, ouvre une session avec `su - nom`, tente l'action, note le résultat (OK ou « Permission denied »), puis fais `exit`.

| Compte | Action | J'anticipe | Résultat |
|---|---|---|---|
| `alice` | `touch /var/partage/JackCelair/commerce/vente/devis.txt` | | |
| `alice` | `ls -l /var/partage/JackCelair/commerce/vente` (groupe du fichier ?) | | |
| `alice` | `ls /var/partage/JackCelair/etudes` | | |
| `bruno` | `cat /var/partage/JackCelair/commerce/vente/devis.txt` | | |
| `bruno` | `touch /var/partage/JackCelair/etudes/mécanicien/plan.txt` | | |
| `carla` | `ls /var/partage/JackCelair` | | |
| `carla` | `cd "/var/partage/JackCelair/direction générale"` | | |

**Je comprends.**

1. Quel est le **groupe** du fichier `devis.txt` créé par `alice` ? Que se serait-il passé **sans** le bit setgid (le `2` de `2770`) ? ______________________
2. Pourquoi `carla` peut-elle lister `JackCelair` mais pas entrer dans `direction générale` ? ______________________
3. Le fichier `devis.txt` peut afficher `r--` pour « autres » : pourquoi `bruno` ne peut-il pourtant pas le lire ? (Regarde les droits du dossier qui le contient.) ______________________
4. **Limite de la politique :** la direction générale doit pouvoir **lire** les dossiers de tous les services. Que faudrait-il faire avec ce que tu connais ? Quel est le défaut de cette solution ? (Indice : un utilisateur dans plusieurs groupes.) ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

1. `grp-commerce`, grâce au bit setgid. Sans lui, le fichier aurait eu **le groupe principal d'`alice`** (par exemple `alice`) : les autres membres du service n'auraient pas pu le modifier.
2. `JackCelair` est en `755` : `carla` a `r-x` (liste et traverse). `direction générale` est en `2770` : « autres » = `---`, donc aucun accès.
3. Pour atteindre un fichier, il faut `x` sur **tous les dossiers du chemin** : `bruno` n'a aucun droit sur `commerce` (autres = `---`), il ne peut donc pas entrer, même si le fichier lui-même est lisible par « autres ».
4. On peut ajouter les comptes de la direction aux **six** groupes, mais ces comptes obtiennent alors aussi l'**écriture** partout (trop de droits). Les listes de contrôle d'accès (`setfacl`) permettent de donner « lecture seule » à un groupe sur un dossier : non traité ici.

Prévisions : `alice` crée `devis.txt` (OK, groupe `grp-commerce`) ; elle ne peut pas entrer dans `etudes` ; `bruno` ne peut ni lire `devis.txt` ni entrer dans `commerce` ; `bruno` crée un fichier dans `mécanicien` (OK) ; `carla` liste `JackCelair` (OK) mais ne peut pas entrer dans `direction générale`.

</details>
