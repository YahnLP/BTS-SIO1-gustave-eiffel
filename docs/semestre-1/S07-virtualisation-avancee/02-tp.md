**J'anticipe.** Avant de lire le cours, note les modes réseau de VirtualBox que tu connais (ou que tu devines d'après leurs noms) et ce que chacun permet : ______________________

**Questions de compréhension**

1. Cite les **quatre principaux modes d'accès réseau** de VirtualBox. ______________________
2. Le mode « **Réseau interne** » isole la VM dans un réseau indépendant et fermé : elle ne communique ni avec l'hôte, ni avec un autre réseau. En suivant cet exemple, **schématise les trois autres modes** (NAT, Réseau NAT, Accès par pont) : qui peut parler à qui ? ______________________
3. Quel **autre paramètre** peut-on modifier pour configurer une carte réseau d'une VM ? ______________________
4. Quelle est la différence entre un stockage à **allocation dynamique** et un stockage **fixe** ? ______________________
5. Qu'est-ce qu'un **snapshot** et à quoi sert-il ? ______________________
6. Quelle est la différence entre un snapshot et une **sauvegarde classique** ? ______________________
7. Pourquoi faut-il **éviter d'accumuler** trop de snapshots ? ______________________
8. Donne un **exemple concret** d'utilisation professionnelle d'un snapshot. ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

1. NAT, Réseau NAT, Accès par pont, Réseau interne (le cinquième, Réseau privé hôte, est cité dans le cours).
2. NAT : la VM sort sur Internet mais n'est pas jointe par les autres VM. Réseau NAT : les VM d'un même réseau NAT se parlent et sortent sur Internet. Accès par pont : la VM est une machine du réseau local, qui parle à tout le monde (hôte, autres machines, Internet). Voir les schémas du cours.
3. Par exemple le type de carte, le mode promiscuité, l'adresse MAC.
4. Dynamique : le fichier grossit selon l'usage. Fixe : tout l'espace est réservé dès la création.
5. Une photographie complète de l'état d'une VM à un instant donné, qui permet d'y revenir (tests, mises à jour, état stable).
6. Le snapshot dépend du disque d'origine et reste au même endroit ; la sauvegarde est une copie indépendante, ailleurs.
7. Performances dégradées, fichiers de différences volumineux, chaîne fragile, sauvegardes compliquées.
8. Par exemple : snapshot d'un serveur avant une mise à jour critique, pour revenir en arrière si elle échoue.

</details>

## Partie C – Le snapshot (≈ 25 min)

**But :** revenir à un état antérieur.

**J'anticipe.** Tu vas installer un logiciel ou changer un réglage visible dans la VM, puis restaurer un snapshot pris **avant**. Que verras-tu après la restauration ? Le logiciel sera-t-il toujours là ? ______________________

1. **Crée** un snapshot : lance la VM Windows, puis menu **Machine** > **Prendre un instantané**. Donne un nom clair (par exemple `Avant installation logiciel X`). **Capture d'écran n° 1.**
2. **Modifie** la VM : installe un petit logiciel ou change un paramètre visible (fond d'écran, par exemple).
3. **Restaure** le snapshot : éteins la VM si nécessaire, puis dans le gestionnaire des instantanés, **restaure** celui que tu as créé. Vérifie que la VM est revenue à son état initial. **Capture d'écran n° 2.**

**Je comprends.**

1. Pourquoi donner un **nom clair** au snapshot ? ______________________
2. Où sont enregistrées les modifications faites **après** le snapshot ? (Pense à la chaîne de disques.) ______________________
3. Pourquoi cela **ne remplace-t-il pas une sauvegarde** ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

1. Pour retrouver l'état voulu : on peut en avoir plusieurs, et le nom doit dire à quel moment ils correspondent.
2. Dans un **fichier de différences** : le disque principal reste figé.
3. Le snapshot dépend du disque d'origine, stocké au même endroit : une panne du stockage perd tout.

</details>

## Partie D – Les Guest Additions (≈ 30 min)

**But :** intégrer la VM à l'hôte.

### D1. Sur Windows

1. Lance la VM Windows.
2. En haut de l'écran, menu **Périphériques** > **Insérer l'image CD des Additions invité**. Si la barre de menu ne s'affiche pas, utilise la combinaison **Ctrl (droite) + C** sur la VM (consigne d'origine).
3. Dans l'explorateur de fichiers de Windows, exécute le CD **VBox Guest Additions**.
4. Termine l'installation et **redémarre** la VM.

**Je comprends.** À quoi sert l'image CD « Guest Additions » ? Pourquoi s'installe-t-elle **dans la VM** et pas sur l'hôte ? ______________________

### D2. Sur Kali

1. Lance la VM Kali.
2. **Périphériques** > **Insérer l'image CD des Additions invité**. En cas d'erreur : **Périphériques** > **Lecteurs optiques** > **Éjecter le disque**, puis recommence.
3. Ouvre un terminal et tape les commandes suivantes :

```bash
sudo mkdir -p /mnt/cdrom
sudo mount /dev/cdrom /mnt/cdrom
cd /mnt/cdrom
sudo sh ./VBoxLinuxAdditions.run --nox11
sudo shutdown -r now
```

**J'anticipe.** Pour chaque ligne, écris ce qu'elle fait avant de la lancer : ______________________

**Je comprends.**

1. Quelle action réalise la commande `mount` ? Pourquoi crée-t-on d'abord le dossier `/mnt/cdrom` ? ______________________
2. Pourquoi faut-il `sudo` ? (Relis le [TP S08](../S08-terminal-commandes-de-base/02-tp.md) si besoin.) ______________________
3. Pourquoi redémarre-t-on à la fin ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

À la partie D1 : l'image contient les pilotes et outils qui intègrent le système invité à l'hôte (copier-coller, dossiers partagés, écran) ; elle s'installe dans la VM car ce sont des pilotes **du système invité**.

1. `mount` **rattache** un périphérique (ici le CD) à un dossier de l'arborescence pour rendre son contenu accessible. Le dossier de destination doit exister.
2. Monter un périphérique et installer des pilotes demandent les droits d'administrateur.
3. Pour que les pilotes installés soient pris en compte au démarrage du système.

</details>

**But :** pour chaque mode réseau, **tester** qui peut parler à qui et **déduire** les communications possibles.

Utilise le [plan d'adressage et de tests](tp/plan-adressage-et-tests.txt). Les commandes de test :

| Besoin | Windows | Kali (Linux) |
|---|---|---|
| Voir la configuration réseau | `ipconfig` | `ip a` (ou `ifconfig`) |
| Tester une adresse | `ping adresse` | `ping -c 4 adresse` |

> [!IMPORTANT]
> **Rappel.** Après chaque changement de mode, **désactive puis réactive** la carte réseau dans le système de la VM. Et si un `ping` vers Windows ne répond pas, **vérifie le pare-feu** de la cible avant de conclure.

### E4. Réseau interne « LAN »

1. Passe les deux VM en **Réseau interne**, nommé **`LAN`**. Réactive les cartes.
2. **Configure à la main** une adresse IP : Windows `192.168.100.1`, Kali `192.168.100.2`, masque `255.255.255.0`.

    - Kali : `ip a` pour repérer le nom de l'interface, puis, en remplaçant `eth0` par ce nom :

```bash
sudo ip addr add 192.168.100.2/24 dev eth0
sudo ip link set eth0 up
```
